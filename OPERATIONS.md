# Sol-arbi
Run with Node 22 using npm ci --ignore-scripts, npm test and npm start. GET / reports mode, state, completed quote checks and the latest route. A running HTTP process can be waiting for credentials.

Set JUPITER_API_KEY in the hosting environment. MODE defaults to scan. The scanner checks direct Jupiter routes from mainnet USDC into ROUTE_MINTS (comma-separated mainnet SPL mint addresses, wrapped SOL by default). The return quote excludes venues used in the outgoing quote. LOAN_SIZES_USDC accepts comma-separated positive whole amounts up to ten million. Gross floor is before borrowing and network costs. A quote alone does not reserve liquidity.

For MODE=simulate supply SOLANA_RPC_URL, USDC_RESERVE (mainnet Save USDC reserve account), and SIMULATION_WALLET (public key). Use a dedicated SOL-funded wallet with existing USDC and intermediate associated token accounts. Eligible routes are composed into one versioned transaction and simulated. Unsupported setup, oversized transactions, disabled loans and insufficient reserve liquidity skip execution. The route search considers Jupiter-supported direct venues for configured pairs and can miss opportunities.

MODE=live reads a Solana keypair JSON from a mounted SIGNER_FILE secret. Keep private keys outside GitHub. It signs only after successful simulation and stops after one submission attempt per process. Restarting a live process re-arms it. Check the wallet history after uncertain submission. MIN_PROFIT_MICRO_USDC and NETWORK_BUDGET_MICRO_USDC both default to 1000000. The latter is an operator estimate of SOL costs in USDC. Failed submitted transactions can incur fees. Review actual costs and run simulation with your own reserve before enabling live execution. A free Render web service may sleep between visits.
